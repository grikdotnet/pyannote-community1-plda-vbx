# Domain docs

This repo uses a single-context layout: root `CONTEXT.md` for domain vocabulary and `docs/adr/` for architecture decisions.

Before exploring an area, read `CONTEXT.md` and any relevant ADRs if they exist. Their absence needs no setup step; create them when domain terms or decisions are resolved.

Use the vocabulary defined in `CONTEXT.md` in issues, proposals, hypotheses, and tests. If a needed term is missing, revisit the name or record the gap for domain modeling.

Surface a conflict with an existing ADR explicitly before proposing a different decision.
